# ระบบยื่นคำร้องแก้ไขผลการเรียน (0 · ร · มส · มผ) — Firebase เวอร์ชัน 1.0 (เฟส 1)

ระบบออนไลน์ 100% ตั้งแต่นักเรียนรู้ผลการเรียน → ยื่นคำร้อง → ครูมอบหมายงาน → ส่งงาน → ครูตรวจ → งานวัดผล → หัวหน้าวิชาการ → ออกบันทึกข้อความ → ผอ. อนุมัติ → ผลการเรียนปรับให้อัตโนมัติ ทุกขั้นลงนามอิเล็กทรอนิกส์และมีประวัติตรวจสอบย้อนหลังได้

## โครงสร้างไฟล์

| ไฟล์ | หน้าที่ |

| `gas-bridge/Code.gs` | Apps Script เก็บไฟล์งานนักเรียนใน Google Drive |

## ติดตั้ง (ประมาณ 30–45 นาที)

### 1. สร้างโปรเจกต์ Firebase (แพ็กเกจ Spark ฟรี)
1. เข้า https://console.firebase.google.com → **Add project** → ตั้งชื่อ เช่น `ppj-grade-fix`
2. **Build → Firestore Database → Create database** → เลือก *Production mode* → Location `asia-southeast1 (Singapore)`
3. **Build → Authentication → Get started** → แท็บ *Sign-in method* เปิด **Email/Password** และ **Google**
4. **Project settings (⚙️) → Your apps → Web (</>)** → ตั้งชื่อแอป → คัดลอกค่า `firebaseConfig`

### 2. แก้ค่าในไฟล์
- `public/config.js` → วาง `firebaseConfig`, ตรวจ `BOOTSTRAP_ADMIN` (อีเมลผู้ดูแลคนแรก) และ `STUDENT_EMAIL_DOMAIN`
- `firestore.rules` บรรทัดบนสุด → `bootstrapEmail()` และ `studentEmailRegex()` ให้ตรงกับ config.js
- `.firebaserc` → ใส่ Project ID

### 3. ติดตั้งตัวเก็บไฟล์ (Apps Script → Google Drive)
1. เปิด https://script.google.com → **New project** → วาง `gas-bridge/Code.gs` → แก้ `FIREBASE_PROJECT_ID`
2. Project Settings → ติ๊ก *Show appsscript.json* → วางเนื้อหา `gas-bridge/appsscript.json`
3. รันฟังก์ชัน `authorize` 1 ครั้งแล้วกดอนุญาตสิทธิ์
4. **Deploy → New deployment → Web app** → *Execute as: Me* · *Who has access: Anyone* → คัดลอก URL ไปใส่ `GAS_URL` ใน `public/config.js`

> ไฟล์จะอยู่ในโฟลเดอร์ "ระบบแก้ไขผลการเรียน - ไฟล์งาน" ใน Drive ของบัญชีที่ deploy แยกตามภาคเรียน/เลขคำร้อง

### 4. Deploy ขึ้น Firebase Hosting
```bash
npm install -g firebase-tools
firebase login
cd grade-fix-firebase
firebase deploy
```
ได้ลิงก์ `https://<project-id>.web.app` (deploy ครั้งต่อไปใช้คำสั่ง `firebase deploy` เหมือนเดิม)

### 5. เริ่มใช้งานครั้งแรก (ผู้ดูแลระบบ)
1. เปิดเว็บ → แท็บ **ครู/บุคลากร** → เข้าด้วย Google ด้วยอีเมล `BOOTSTRAP_ADMIN` → ระบบสร้างบัญชีผู้ดูแลและค่าตั้งต้นให้อัตโนมัติ
2. **ตั้งค่าระบบ** → ตรวจปีการศึกษา/ภาคเรียน ชื่อ ผอ. ส่วนราชการ ฯลฯ (ใส่ URL รูปครุฑได้)
3. **บุคลากร/สิทธิ์** → วางรายชื่อครูจาก Excel (อีเมล ⇥ ชื่อ ⇥ ตำแหน่ง ⇥ กลุ่มสาระ) แล้วกำหนดบทบาท *หัวหน้างานวัดผล / หัวหน้าวิชาการ / ผู้อำนวยการ*
4. **นำเข้าผลการเรียน (แนะนำ: PDF ปพ.6)**
   - ใน SchoolMIS: **รายงานเอกสารการศึกษา → ปพ.6 แบบมีคะแนน** → เลือกปีการศึกษา/ภาคเรียน → กดปุ่มแดง **"พิมพ์ทั้งห้อง"** → กดดาวน์โหลด PDF ทำทุกห้อง
   - ในระบบใหม่: เมนู **นำเข้าผลการเรียน** → เลือกไฟล์ PDF ทั้งหมดพร้อมกัน → ตรวจตัวอย่าง → กดนำเข้า
   - ระบบอ่านเลขประจำตัว ชื่อ ชั้น/ห้อง ปีการศึกษา ภาคเรียน รหัสวิชา ชื่อวิชา หน่วยกิต และผลการเรียนจากไฟล์ (ทดสอบกับ PDF จริงของโรงเรียน ม.6/2: อ่านถูก 112/112 รายการ) รายวิชาที่ยังไม่มีผลจะข้ามไป
   - อ่านไฟล์ในเครื่องของผู้ใช้ ไม่ส่ง PDF ไปที่อื่น
   - ยังรองรับไฟล์ Excel/CSV (แถวละ 1 รายวิชา หรือแถวละ 1 นักเรียน) ด้วย
   - นำเข้าซ้ำได้ (อัปเดตข้อมูลเดิม ไม่สร้างนักเรียนซ้ำ และไม่ทับผลที่ ผอ. อนุมัติแก้ไขแล้ว)
5. **รายวิชา–ครูผู้สอน** → PDF ปพ.6 ไม่มีชื่อครู จึงต้องกำหนดครูให้แต่ละรายวิชา/ห้องที่นี่ (ติ๊ก "เฉพาะที่ยังไม่มีครู") — คำร้องที่ยื่นก่อนกำหนดครูจะส่งถึงครูอัตโนมัติเมื่อกำหนดแล้ว
6. **นักเรียน/รหัสเริ่มต้น** → **นำเข้าเลขประจำตัวประชาชน** (ไฟล์ Excel รายชื่อที่มีคอลัมน์ "เลข ปปช." และ "เลขประจำตัว" อ่านทุกชีต)
   - นักเรียนเข้าครั้งแรก: **ชื่อผู้ใช้ = เลขประจำตัวประชาชน 13 หลัก · รหัสผ่าน = เลขประจำตัวนักเรียน** แล้วเปลี่ยนรหัสผ่านเองภายหลัง (มีแถบเตือนจนกว่าจะเปลี่ยน)
   - ระบบ**ไม่เก็บเลขประจำตัวประชาชน** เก็บเฉพาะค่าเข้ารหัส (SHA-256) และห้ามดึงรายการ
   - เลขประชาชนซ้ำกันระหว่างนักเรียนต่างคน → ระบบไม่ผูกให้และแจ้งรายชื่อ ใช้ **พิมพ์ใบรหัส** (รหัสสุ่ม 6 ตัว) แทน เช่นเดียวกับนักเรียนที่ไม่มีเลขประชาชน
   - ลืมรหัสผ่าน: กด **รีเซ็ตรหัส** → นักเรียนเข้าใหม่ด้วยเลขประชาชน + เลขประจำตัวนักเรียน
7. บุคลากรที่ต้องลงนามทุกคน → เมนู **ลายเซ็นของฉัน** → วาดหรืออัปโหลดลายเซ็น

## การใช้งานตามบทบาท

| บทบาท | ทำอะไร |
|---|---|
| นักเรียน | เข้าครั้งแรกด้วยเลขประชาชน + เลขประจำตัว → ปุ่ม 🖨️ พิมพ์ผลการเรียนของตัวเอง → เห็นผลการเรียนทุกภาคเรียน → ระบบแจ้งวิชาที่ติด → กด **ยื่นคำร้องแก้ไข** → ส่งงาน (แนบไฟล์) → ติดตามสถานะแบบเรียลไทม์ |
| ครูผู้สอน | **คำร้องถึงครู** → รับเรื่อง/มอบหมายงาน+กำหนดส่ง → ตรวจงาน → ผ่าน (เลือกผลใหม่ตามเกณฑ์ + ลงนาม) / ให้แก้ไขงาน / ไม่ผ่าน |
| หัวหน้างานวัดผล | ตรวจความถูกต้อง + ลงนาม หรือส่งกลับครู · นำเข้าข้อมูล · จัดการนักเรียน/รายวิชา |
| หัวหน้าวิชาการ | ตรวจ + ลงนาม → **บันทึกข้อความ** เลือกหลายคำร้อง → ออกเลขที่อัตโนมัติ + ลงนามเสนอ |
| ผู้อำนวยการ | **รอ ผอ. อนุมัติ** → เปิดบันทึก → อนุมัติ (ลงนาม) / ส่งกลับแก้ไข / ไม่อนุมัติ → ผลการเรียนปรับอัตโนมัติ |
| บุคลากรทุกคน | **ผลการเรียนนักเรียน** เลือกห้อง/ค้นหาเลขประจำตัว → ดูทุกภาคเรียน → **พิมพ์รายคน / พิมพ์ทั้งห้อง** (A4 หน้าละ 1 คน, บันทึก PDF ได้) วิชาที่แก้แล้วแสดง "แก้ไขจาก 0 ตามบันทึกที่ …" |
| ทุกฝ่าย | **ติดตามคำร้องทั้งหมด** ค้นหา/กรอง/ดาวน์โหลด CSV · **ภาพรวม** สถิติ + รายชื่อนักเรียนที่ติดแต่ยังไม่ยื่น |

เกณฑ์ผลการเรียนใหม่ (แก้ได้ในตั้งค่า): แก้ 0 ได้สูงสุด 1 · แก้ มส ได้สูงสุด 1 · แก้ ร ได้ 0–4 · แก้ มผ ได้ ผ · ยื่นได้สูงสุด 2 ครั้งต่อรายวิชา

## ความปลอดภัยและความโปร่งใส
- **Security Rules บังคับที่เซิร์ฟเวอร์** ไม่ใช่แค่ซ่อนปุ่ม: นักเรียนอ่านได้เฉพาะข้อมูลตัวเอง ครูอนุมัติได้เฉพาะวิชาที่ตนสอน แต่ละบทบาทเปลี่ยนสถานะได้เฉพาะขั้นของตัวเองและแก้ได้เฉพาะช่องที่กำหนด ผลการเรียนใหม่ต้องอยู่ในเกณฑ์
- ทุกการลงนามบันทึกชื่อ ตำแหน่ง และเวลาของเซิร์ฟเวอร์ (ปลอมเวลาไม่ได้) ประวัติการดำเนินการเพิ่มได้อย่างเดียว ลบ/แก้ไม่ได้
- ถ้าส่งกลับ ลายเซ็นของขั้นนั้นจะถูกยกเลิก ต้องลงนามใหม่
- ไฟล์งานเปิดได้เฉพาะผู้เกี่ยวข้องกับคำร้อง (ตรวจสิทธิ์ผ่าน Firestore ทุกครั้ง)
- บุคลากรเข้าด้วย Google เท่านั้น (อีเมลยืนยันแล้ว) ไม่มีรหัสผ่านให้รั่ว

- กรณีแก้ ร แล้วได้ 0 ต้องให้งานวัดผลดำเนินการแก้ 0 ต่อนอกระบบ (เวอร์ชันนี้ยังไม่รองรับต่อเนื่อง)

## ทดสอบ Security Rules ก่อนใช้งานจริง
ผมทดสอบหน้าเว็บครบทุกขั้นแล้ว (ด้วยฐานข้อมูลจำลอง) แต่กฎ `firestore.rules` ยังไม่ได้ทดสอบกับ Firebase จริง ก่อนเปิดใช้ แนะนำให้ทดลองทั้งเส้นทางด้วยบัญชีทดสอบ 1 รอบ:
1. `firebase deploy` แล้วเปิด Firebase Console → Firestore → **Rules** (ถ้า deploy ไม่ผ่านจะแจ้งบรรทัดที่ผิด)
2. ทดลองครบเส้นทางด้วยนักเรียนทดสอบ 1 คน + ครูทดสอบ ถ้าขั้นไหนขึ้น "ไม่มีสิทธิ์ทำรายการนี้" ให้ส่งข้อความ error มา จะแก้ให้
3. ใช้ **Rules Playground** ในหน้า Rules ทดลองว่านักเรียนคนหนึ่งอ่านผลการเรียนของคนอื่นไม่ได้
